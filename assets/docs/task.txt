Pipeline Specification: Fail-Stop, No Retries, No Fallbacks
Core Principle

One model per stage.
If a stage fails → pipeline stops immediately and raises a StageError.

This specification applies to the 'Transcripts' configuration which will become unlike the other configurations when re-written.  It will be a pipeline to process the stored transcript.  The transcript is stored at assets/data/transcripts/rawtranscript.txt

the .yaml file will specify the model for each stage

handleruntasksClick() in toolbar.js , now a stub will call into a new javascript container that will defined by

file processtranscript.js :

const transcriptmodule = (function () {

  // private variables
  let internalstate = {}

  // private functions
  function helper(data) {
    return data.trim()
  }

  // public function
  function processtranscript(input) {
    const cleaned = helper(input)
    
    // do processing here
    internalstate.last = cleaned

    return cleaned
  }

  // expose public API
  return {
    processtranscript: processtranscript
  }

})()


Having the code that implements the pipeline below in it's own file 'processtranscript'js' will better organize things.



You have freedom to refine and modify transcript.yaml, the new javascript file, and toolbar.js to call the new js file.  Do not modify the rest of the code base.  This task is only to implement the transcript pipeline.  Status messages will be written to status on the toolbar and the final output will be displayed as output is already displayed by the other configurations.



Error Handling (All Raise StageError and Stop)
Failure Type	Action
Timeout	Raise StageError, stop pipeline
Empty response	Raise StageError, stop pipeline
Model not found	Raise StageError, stop pipeline
Out of memory	Raise StageError, stop pipeline
Malformed output	Raise StageError, stop pipeline

    ❌ No automatic retries

    ❌ No fallback models

    ✅ User changes the model variable and reruns
